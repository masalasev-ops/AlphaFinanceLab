# 5.1 — The provider seam: Batches, caching, per-task tiering (FR-21)

**Status: DONE (v1.9.61).** The first `src/` change to `AlphaLab.Llm` since Phase 0 created it empty.

## Read first

`BUILD_AND_PROMPTS` FR-21; MASTER §7 (token economics), §23.2 (the L0/L1/L2 layering); INTEGRATIONS §5
(Anthropic) + §9 (the shared client rules); CONFIG_REFERENCE `Llm`; SCHEMA (`analysis_cache`,

## Build

Implement `IAnalysisProvider` on the Message Batches API with prompt caching on the static block and
per-task model tiering from config. Create the three LLM tables. Enforce the D24 budget **before any token
is spent**.

### The layering that makes the economics work

L0 (static instructions + schema) and L1 (the lesson set) form the **cacheable prefix**; L2 (the day's
fresh block) is charged every call. Caching is a **prefix match**, so order is load-bearing: anything
volatile placed before the breakpoint invalidates everything after it, and — because a cache *write* costs
more than an uncached read — a silent invalidator makes caching a pure surcharge rather than a saving.
Put the breakpoint on the last system block; put L2 in the user turn.

### Rails specific to this checkpoint

- **The budget is enforced pre-flight, never reconciled after.** Cache first (a hit must not consume
  headroom it does not need), budget second, spend last. Record the API's *actual* usage, never the
  estimate; the estimate exists only to decide.
- **Results come back in ANY order.** Correlate by `custom_id`, never by position. Rebuild the response in
  request order.
- **A refusal is an HTTP 200** with `stop_reason: "refusal"` and empty or partial content. Check
  `stop_reason` before reading `content` — code that indexes `content[0]` breaks here, on a success status.
- **No sampling parameters.** `temperature`/`top_p`/`top_k` do not exist on the pinned tier and are
  rejected with a 400. Behaviour is steered by prompt.
- **`max_tokens` caps thinking AND response text together** on this tier. Size with headroom.
- **A failed or late batch is a no-read day**, not an exception. Forward-only makes that safe: the read
  would only have informed subsequent days.

## Traps discovered while building this — do not re-derive them

1. **`AlphaLab.Llm` may not reference `AlphaLab.Data`** (`ci.ps1` reference graph), and the shared
   resilient client lives in Data and was **GET-only**. INTEGRATIONS' recorded "inherits the shared client"
   was therefore *not reachable* (finding 323). Resolved with two narrow additions rather than a second
   HTTP stack: `IResilientHttpSender` (a **separate** interface adding POST + per-request headers — adding
   them to `IResilientHttpClient` broke three existing test stubs that had no reason to care) and
   `IModelTransport` in Core, which Data satisfies. The resilience policy stays in one place; the LLM layer
   holds no transport concerns and is fully unit-testable with a fake transport.
2. **The API key goes on the request, not the shared `HttpClient`** — that client also serves EODHD,
   BlackRock and Wikipedia.
3. **`Llm.DegradationOrder` hits the finding-301 binder trap** (a configured collection *appends* to a
   populated default, so the operator cannot remove an entry — and here the un-removed entries stay
   *ahead* in priority). Default it empty; resolve via a `Resolved*` accessor.
4. **Pricing belongs in config, not code.** Rates are vendor facts with a date; an unpriced model must
   **throw**, because a zero cost is indistinguishable from a free cache hit in `llm_budget_log`.
5. **`analysis_cache` did not exist yet**, which made finding 317's three-vocabulary problem free to fix
   at `CREATE TABLE` and finding 319's missing CHECK free to add. Both closed here; a later value now costs
   a migration (finding 121's rule).
6. **ScratchStore classification is not bookkeeping.** All three tables are **Untouched**, because
   rewinding `analysis_cache` would delete the row `reproduce-day` must replay and force the choice between
   calling the model (forbidden by D105) and having no answer.

## Gate

`FR21_CacheHit_CostsZero` — and assert it **three ways**: nothing reported, nothing reached the transport,
nothing charged to the day. A cache that calls the API and then reports zero passes the weak version.

Plus: batch correlation by `custom_id` (script the results **reversed** — a positional implementation
passes every other test), all four `result.type` kinds, refusal-before-content, the three D24 ceilings,
partial admission (never a blackout), a mocked month under budget, and the `[Trait("Category","LiveSmoke")]`
test excluded from both CI legs by `--filter "Category!=LiveSmoke"`.
