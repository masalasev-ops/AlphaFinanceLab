# 5.7 — The D110 proposal-quality INPUTS + the D113 paper control

*The checkpoint the corpus named by number long before the rest existed.*

## Read first

MASTER §2 rows **D110** and **D113**; §23.4 (the per-proposal bullets); SCHEMA `journal_entries`
(`prior_prob`, `detectability_floor_ann`); CONFIG_REFERENCE (the two `Kpi.Proposal*` rows); TEST_PLAN §6;
`DetectabilityGate.cs`.

## Build — INPUTS ONLY

**The scorer, the read-model, the `/api/v1` route and the panel are NOT built here.** This checkpoint
captures the inputs so the chained criterion has no missing first link; the rest follows once proposals
exist. A scorer built now is a consumer for data that does not exist, and the route would serve an
`insufficient` series for years.

1. **Migration M10:** `journal_entries.prior_prob`, `journal_entries.detectability_floor_ann` — both
   nullable and additive.
2. **`prior_prob` as a request field** on the hypotheses endpoint, in (0,1). Refuse a *researcher*
   proposal without one; an operator-authored hypothesis may carry NULL.
3. **Persist the floor at ASSESSMENT** (D113's amendment to D110) via a new `DetectabilityGate.Assess`
   call site on the unlocked draft. `CandidateFactory` also persists the floor it already computes and
   currently discards.
4. **Pin the two score parameters as versioned config rows BEFORE the first proposal exists** —
   `Kpi.ProposalPriorClamp`, `Kpi.ProposalScoreMinClosed` — via a new Worker verb on the
   `signal-pin-thresholds` model: both values required and explicit (never defaulted — a silent default
   defeats the pin-before-use discipline), an already-pinned key left untouched and reported, each row
   recording its derivation in `reason`.

**Why config rows and not appsettings:** they are score *inputs*, so a mid-experiment change breaks the
proposal-to-proposal comparability the chain depends on — and an appsettings value is not as-of resolvable
(the D106 `GateOptions` limit), so a later recomputation could not reproduce the score a proposal was
originally given. Same shape and reasoning as D108's two trend alphas.

## The D113 paper control

- The **same seat with the evidence-prior seam disabled or placebo'd** — *that difference is what the
  control controls for*. Without it, two identical researchers produce a margin difference of zero by
  construction.
- **Never admitted** ⇒ writes no `trials_registry` row ⇒ costs zero trials.
- **Assessed in the same job run as the treatment arm, before any admission**, so both resolve an
  identical floor (the floor is current-state resolved; one intervening admission moves it by a Bonferroni
  step).
- **Budget pairing:** both arms draw on `Ai.Researcher.MonthlyBudgetUsd`. Exhaustion between them would
  emit a treatment proposal with no control — an unpaired observation silently entering the margin series.
  **Check headroom for the pair before dispatching either.**

## The uncomputable-floor case — no third column

`DetectabilityGate.Assess` returns `Details = null` on the `unassessed_no_sigma` branch (no `power_reports`
row with σ > 0 for either run kind). Phase 4's calibration wrote replay rows so this is satisfied today,
but **assert it rather than assume it**.

A proposal with no computable floor is permanently unscorable on the margin channel. **Refuse it with a
named reason and count it through D112's machinery** — no schema change, D110's two-column scope intact,
and the loud failure comes from a mechanism 5.6 already built.

## Three rails, structural not documentary

- The score is **mechanically computed, never LLM-computed** (rule 32 bars AI from *judging*, not from
  being *measured*).
- **The researcher never reads its own score** — it reads closed journal *outcomes*, so **no context-pack
  field may carry the score**. Enforce as a whitelist closure, the `FX-PackNoLeak` shape.
- The margin is **recorded but never read as a quality signal until the control arm exists** — which,
  under D113, it now does from this checkpoint.

## Gate

- `FX-ProposalPriorRequired` — no prior ⇒ refused; the draft persists **both** `prior_prob` and the
  assessment-time floor; the uncomputable-floor branch refuses and writes **zero** rows.
- `FX-ProposalScorePinBeforeProposal` — either parameter unpinned ⇒ the endpoint refuses, fail-closed,
  naming the missing key, writing **zero** `journal_entries` rows. **Both halves** (pin, then assert it
  proceeds).
- `FX-ProposalScoreIsMechanical` — a pure function of (stated prior, measured outcome, stored floor)
  reaching **no** model provider; plus the R1 closure: a score added to the pack builder **fails**.
- Two D113 fixtures: **budget exhaustion abstains both arms, never one**; and the arm difference — the two
  packs differ **only** in the digest field, at identical token count under placebo.
