# 5.3 — Stage 3 of the D53 pipeline + the daily regime brief

## Read first

`BUILD_AND_PROMPTS` FR-29; MASTER §20.4 (the staged pipeline), §7 (the regime brief); RUNBOOK §3 + the
failure table; CLAUDE.md rule 12; TEST_PLAN §3 (`FX-StagedPipeline`) and §6.

## Build

Wire the LLM as **Stage 3** of the D53 daily pipeline:

- The batch is submitted **after Stage 2 commits**, and its results land in **their own transaction**
  whenever they arrive.
- The daily regime brief writes structured output to `analysis_cache` keyed `(prompt_hash, model, as_of)`.
- **Catch-up runs Stages 1–2 only.** No LLM for past days — structurally, not by a flag.
- **Replay has no LLM path by construction**: the replay composition root registers no
  `IAnalysisProvider`. Compile-time absence is preferred to a runtime guard.

## Why the post-commit boundary is the whole point

The invariant is one atomic **write** transaction per trading day (golden rule 16). If the LLM stage ran
inside it, a slow or failed model call would roll back a day's committed trades — the arena's state would
become hostage to a vendor's latency. Post-commit inverts that: **a late or failed batch is a no-read day**
and nothing else. Forward-only (D16) is what makes that safe rather than merely tolerable — the read would
only ever have informed *subsequent* days, so its absence costs nothing already committed.

This is also why Stage 3 must never write anything Stage 2 reads. If it did, the "own transaction" would
be a lie: the day's state would depend on whether the batch came back.

## Rails

- The Worker remains the **sole DB writer** (D59). Stage 3's transaction is still the Worker's.
- Jobs never run inside a daily write transaction (D72): the OnDemand launch order stays
  schema → catch-up → drain jobs → backup → exit.
- A no-read day is logged (`llm_budget_log`), not silent — the difference between "we chose not to read"
  and "we could not tell" must survive in the record.

## Gate

- `FR21_Replay_HasNoAnalysisPath` — a replay produces **zero** `analysis_cache` rows, proven by the
  absence of a registration rather than by a runtime assertion.
- The FR-29 post-commit test: a mocked batch result lands **after** the Stage-2 commit, in its own
  transaction; a Stage-1 provider failure still leaves **zero** DB writes.
- Catch-up over a multi-day gap makes **no** model calls.
- Record the mocked-month cost in the PROGRESS gate box (it has a `$___` slot).
