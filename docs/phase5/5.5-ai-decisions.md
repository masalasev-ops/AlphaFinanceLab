# 5.5 — `ai_decisions` persist-before-use, per-seat budgets, reproduce-day (D81/D105/D24)

## Read first

MASTER §23.3 (contestant rules 1–5), §23.8.1 (the four artefacts), §23.8.5 + §13.5 (reproduce-day);
SCHEMA `ai_decisions`; CONFIG_REFERENCE `Ai.*`; TEST_PLAN §6.

## Build

**The persisted row IS the decision.** One call per `(strategy, asOf)`; the response persists to
`ai_decisions` **before** use; the funnel consumes the stored row and any re-run replays it, never
re-calling. Determinism for AI-seated strategies reads **f(inputs, watermark, seeds, stored AI outputs)**.

### All four artefacts — (c) is the one that gets dropped

| # | Store | Catches |
|---|---|---|
| a | the exact context pack **as stored bytes** | wrong input |
| b | the **raw** model output, not only the parsed result | misparse |
| c | the parsed decision **AND what the funnel actually did with it** | misapplication |
| d | model string, prompt version, sampling/effort config | behaviour change after a model swap |

**(c) is the one most easily lost**, because (a) and (b) together prove what was asked and answered while
neither shows what the arena *did*. Without it, a correct decision and a correct log can coexist with a
wrong trade and nothing in the record would show it. A guardrail rejection, a sizing clamp or a cash
constraint between the decision and the fill is exactly the case this exists for.

**On (d):** the pinned tier has **no sampling parameters** — `temperature`/`top_p`/`top_k` are rejected.
What there is to persist is the **effort and thinking configuration**. The artefact is satisfied by
recording what actually exists, not by recording a field that does not.

### Per-seat budgets

`Ai.Contestant.DailyBudgetUsd`, `Ai.Researcher.MonthlyBudgetUsd`. **On exhaustion the contestant
abstains** — an empty score map, the funnel's honest "nothing scored today" — never a padded or
cached-stale decision. The researcher's job simply queues.

### Reproduce-day (D105)

`reproduce-day` resolves an AI decision by **replaying the stored row**, making **zero** model calls.
Classify `ai_decisions` as **Untouched** in `ScratchStore`: rewinding it would delete the very row the
replay depends on, leaving the choice between calling the model (forbidden) and having no answer. Classify
`ai_context_packs` deliberately too, and state the reason at the classification — the 5.1 LLM tables set
the precedent.

## Rule 32 — build the guard, don't just write the rule

These artefacts are read by humans and by **nothing that judges AI output**. Add a **structural guard** on
the `DescriptiveOnlyGuardTests` model — an assembly-scoped, default-deny reflection closure asserting that
no type in a monitor / gate / allocator / population path, **and no context-pack field**, reads
`ai_context_packs` or `ai_decisions`.

This matters because rule 32 is still prose-only in the repo (the Signal Library's boundary was the first
structural enforcement of a "never an input to X" rule). A debugging surface is exactly the sort of thing
that erodes such a rule by convenience — someone wires a pack field to a prior decision "just to see", and
AI output is now an input to the thing that prices AI output.

**The model's stated reasoning is more output, not a causal account.** Log a rationale when it arrives free;
never build a debugging path that depends on it, and never let any of the above consume it as evidence.

## Gate

- `FX-AiDecisionIsTheRow` — a re-run consumes the stored row; the provider seam proves **zero** API calls.
- `FX-BudgetAbstain` — an exhausted per-seat budget yields an empty score map ⇒ a sparse wish list, never
  a stale, cached or padded decision.
- `FX-ReproduceDay-AiSession` — `reproduce-day` on a committed AI-seated session is byte-identical with
  **zero** model calls. Without it, `FX-ReproduceDay`'s byte-identical assertion is unsatisfiable for any
  AI-seated session — a live call returns something different and fails on a *correctly-committed* day.
