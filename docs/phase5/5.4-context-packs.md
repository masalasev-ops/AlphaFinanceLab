# 5.4 — `ContextPackBuilder` + `ai_context_packs` (D80/D104)

*The highest-leverage checkpoint in the phase: `FX-PackNoLeak` is, per §23.8.2, the single highest-value
check in the whole AI-seat design — leakage into a pack is invisible in every downstream number and would
invalidate the twin comparison that prices the seat.*

## Read first

MASTER §23.2 (the pack contract), §23.8 (all of it), §24.6 (the digest + the reproduce-day trigger);
SCHEMA `ai_context_packs`; CONFIG_REFERENCE `Ai.PackRecipeVersion`; TEST_PLAN §6; D96 (`ResolveAsOf`),
D104, D110 R1, D113.

## Build

- `ContextPackBuilder` assembling packs for `(seat, strategy, asOf, watermark)` **exclusively** through the
  versioned read services / `IFeatureView`. **Raw series never enter a prompt** — derived features only.
- Persist to `ai_context_packs` with SHA-256 `pack_hash`, `token_estimate`, `recipe_version`.
- L0/L1/L2 layering for cache stability.
- **Migration M8:** `ai_context_packs`, `ai_decisions`.

### Where it lives, and why it is not in `AlphaLab.Llm`

The builder must read the versioned read services, which live in `AlphaLab.Data` — and `ci.ps1` allows
`AlphaLab.Llm` only `Core`. So the builder goes in **`AlphaLab.Evaluation`** (a new `Ai/` folder), which
can reach both. That folder also sits outside the `ci.ps1` descriptive-only path grep
(`Evaluation/{Allocator,Gate,Candidates,Power}` + `Core/Funnel`).

### The digest, and the seam's three modes

Wire the D91 signal digest — one line per signal (1y rank-IC, 5y rank-IC, trend flag) — through the
evidence-prior seam via **`ResolveAsOf`**, never `ResolveCurrent`. Consume the FR-46 read-model's **DTO**;
never `ISignal`, `SignalGrade` or `SignalContext`, because `DescriptiveOnlyGuardTests` is an
**assembly-scoped, default-deny** closure over Core + Evaluation and will redden on the signature.

**Build `on` / `disabled` / `placebo` as first-class modes.** They are not decoration: D113's control arm
is built from them, and the **placebo must hold pack shape and token count constant** (shuffled or
synthetic grades of identical form) so a measured arm difference cannot be an artefact of prompt length.

### The arena floor as a COMMON pack field

Publish the arena's detectability floor as a pack field, resolved **as-of** through D96 so `FX-PackNoLeak`
holds per-field. It is **common** — the control arm receives it too; the digest is the arm difference.

**It cannot call `DetectabilityGate.Assess`.** That method resolves *current* state by design
(`ResolveCurrent(DetectionPower)`, a live trials count, the most recent 50 `power_reports`) because
"admission is an operational act, not a run-scoped read". Wiring the operational path into a pack puts a
post-as-of fact in it. Build an **as-of variant**: trials count as-of, σ as-of, `DetectionPower` through
`ResolveAsOf`.

**Why publishing it does not breach D110 R1** — record this, or a later reader will read it as a breach.
R1 forbids the researcher reading **its own score**. The floor is a **measured property of the arena**, the
bar every candidate faces — not a grade on the researcher. Different object, different rail. And
withholding it protects nothing: D79 already grants closed journal outcomes, from which the floor can be
reconstructed *slowly and wrongly*; publishing replaces a bad inference with a good fact.

Consider on the same grounds the **per-rule floor-over-signal ratio** (finding 307: the floor exceeds
`|mean rank-IC|` in all 14 pairs, 1.97×–116×, median 6.9× — so every rule reads `gone` while the ratio
still orders them). It is per-signal, so it rides the digest and lands on the **treatment** side unless
D113 says otherwise.

### The reproduce-day obligation

**Move `signal_ic` from `Untouched` to `RewoundTables`.** This is arrival (b) of the two-arrival trigger
recorded at its own `ScratchStore` classification: once a grade can enter a pack, a reproduced session's
pack would contain a grade **that session itself produced** — a D104 leak. `FX-PackNoLeak` would catch it;
the rewind *prevents* it, and prevention is the better place for a leak that would otherwise be found only
after a reproduction had been trusted.

## Gate

- `FX-PackWatermark` — a pack built at watermark W is **byte-identical** regardless of later bars/actions.
- `FX-PackNoLeak` — two **closure-style** assertions: (1) no field carries an `observed_at` later than the
  simulated as-of, **per field**; (2) a pack contains **only** whitelisted fields, so a field added to the
  builder and not the whitelist **fails** rather than passing silently.

**Keep them distinct.** Byte-identity does not imply leak-freedom: a pack that deterministically includes a
post-as-of fact is byte-identical every time and still leaks. Neither implies the other; both are required.
