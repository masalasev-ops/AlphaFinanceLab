## Build

Three endpoints under `/api/v1/analysis/`: `brief`, `skeptic`, `hypotheses`.

- **Validate synchronously → 422; then enqueue → 202 + job_id.** The Api never runs long work on a request
  thread (rule 19), and it may not reference `AlphaLab.Llm` (`ci.ps1`) — so it validates against Data/
  Evaluation, writes a `jobs` row, and the Worker executes.
- **503** when the D24 budget is exhausted.
- **Parent evidence required** — an outcome id, a finding, or an attribution row. **422 without one.**
  This is what makes the loop grow from measured outcomes rather than vibes.
- Output is a **draft, unlocked** `journal_entries` row (`kind='hypothesis'`). **The AI proposes; only the
  operator pre-registers** (rule 30). Locking is the operator's act and nothing else's.
- Subject to the **D89/FR-40 detectability gate** — a proposal whose expected effect could not clear the
  NW-MDE within `Gate.DetectabilityHorizonYears` is refused, so the loop cannot spend trials budget on a
  claim the arena can never adjudicate.
- Surface `Research.ForkBudgetPerYear` + `Research.MaxConcurrentCandidates` beside the deflated-Sharpe
  trials count — the improver rations itself because every trial spends everyone's significance.
- Brief and skeptic outputs persist as **linked** `journal_entries` (D52).
- **Migration M9:** `jobs.kind` gains `analysis_hypotheses` (finding 121's rule — enum CHECKs extend only
  by migration).

## The D112 evidence diet

Refuse (422, named reason) once the **count of overdue journal outcomes** — past their declared
`evidence_window_days`, still unclosed — reaches **`Research.MaxConcurrentCandidates`**.

Three things the implementation must get right, because the mechanism is misreadable otherwise:

1. **No new config key.** The bound is derived; do not add a days threshold.
2. **The trigger is OPERATOR behaviour.** It is a forcing function on the human who owes a closure, never
   a penalty on the seat. Name it that way in the error message.
3. **Count the refusal and expose the count** for rendering beside the D110 score. A blocked proposal is a
   **gap in the proposal stream**, and an uncounted gap is indistinguishable from researcher inactivity
   when it is in fact operator debt.

The same refusal machinery carries D113's unscorable-proposal case at 5.7 (a floor that cannot be
computed) — build it once, with a named-reason enum, not as a one-off.

## Rails

- The `/analysis/*` commands return **202 + job_id**, never a blocking result (FR-32).
- The D60 error envelope with the right status: 422 validation, 409 run-in-progress, 503 budget.
- The §1.2 **researcher-yield KPI is measured from this checkpoint** — it needs hypotheses to exist.

## Gate

- `FR23_Hypotheses_RequireParentEvidence` — no parent evidence ⇒ 422; an accepted proposal lands
  **unlocked**; only the operator's lock registers it; the fork budget decrements and renders.
- `FX-EvidenceDietRefusal` — at the bound ⇒ 422 with its named reason, zero rows written, refusal
  **counted**; below the bound (one or two late outcomes) ⇒ proceeds. Both halves.
- `FR32_LongRunningCommand_Returns202Job`.
